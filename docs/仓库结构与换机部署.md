## 3. 兼容软链清单（**为的是零改动源码**）

原仓库里 `client/`、`server/`、`shared/` 是**同级兄弟目录**，源码用相对路径互相引用；按「端 + 前后端」拆层后，用下面 10 条软链把原路径关系补回来。若你更希望**零软链**，我可以改成直接修补 3 处路径常量（`main.py` 的 `../shared`/`../server`、`app.py` 的 `ROOT/client/web`）。

| 软链 | 作用（对应源码里的写死路径） |
|---|---|
| `win/frontend/web → ../../web/frontend` | `main.py:1435` 加载 `<自身目录>/web/index.html` |
| `win/frontend/agent_client.py → ../backend/agent_client.py` | `main.py` 从自身目录 `import agent_client` |
| `win/backend/shared → ../../web/backend/shared` | 规则管线单一真源（不在 win 侧复制一份） |
| `win/backend/server → ../../web/backend/server` | 服务层单一真源（桌面端 server 模式自动拉起的就是它） |
| `win/shared → backend/shared` | `main.py` 的 `dirname(dirname(__file__))/shared` |
| `win/server → backend/server` | `main.py` 的 `../server`（`llm_config` 导入、自动拉起 `app.py`、`SERVER_DATA_DIR`） |
| `win/client/web → ../frontend/web` | 从 `win/server/app.py` 启动时 `app.py` 的 `ROOT/client/web` 静态挂载 |
| `win/webui → ../web/frontend/legacy-webui` | 同上 `ROOT/webui` |
| `web/backend/client/web → ../../frontend` | 从 `web/backend/server/app.py` 启动时 `ROOT/client/web` 静态挂载 |
| `web/backend/webui → ../frontend/legacy-webui` | 同上 `ROOT/webui` |

> ⚠️ 拷到 **Windows / FAT32 / exFAT** 或发 zip 前，软链需实体化：`cp -RL DermAgent DermAgent-flat`（会按引用展开，体积 +≈110MB）。macOS/Linux/APFS 下可直接使用。

## 4. 怎么跑

### 4.1 Web 端（主链路：服务层 + 浏览器/PWA）
```bash
cd DermAgent/web/backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cd server && python app.py            # 默认 8765；PORT=9000 python app.py 可改端口
# 浏览器打开 http://127.0.0.1:8765/     安卓端同址（局域网 http://<电脑IP>:8765/）
```

### 4.2 Windows 桌面端（PySide6）
```bash
cd DermAgent/win/frontend
python3 -m venv .venv && source .venv/bin/activate
# ⚠️ 必须同时装服务端依赖：main.py 用 `sys.executable` 自动拉起 server/app.py（同一个解释器/同一个 venv）
pip install -r requirements.txt -r ../../web/backend/requirements.txt
python main.py                        # server 模式：自动拉起本机服务层（win/server/app.py）
```
> 只装 `requirements.txt`（PySide6 + Pillow + pytest）时，**mock 模式正常，但 server 模式会因缺 fastapi/uvicorn 起不来**。
> 原仓库的 `client/requirements.txt` 未列服务端依赖（实际开发时用的是一个装了全套的 venv），这里按实测补齐。
- **mock 模式**：完全离线（`win/backend/agent_client.py` + `shared/derm_core.py` 确定性管线），断网可演示。
- 打包 Windows 可执行：`pyinstaller --name Fuzhi3D --windowed --add-data "web:web" main.py`（须在 Windows 上执行）。

### 4.3 安卓端
```bash
cd DermAgent/web/frontend/android && bash build_apk.sh   # 零 Gradle：aapt2 + javac + d8 + zipalign + apksigner
# 需要 ~/derm-build-tools 下的 JDK 与 Android SDK 34（minSdk 24 / target 34，debug 签名）
```
> ⚠️ 脚本里产物路径写死为 `../web/dermagent.apk`（原仓库 `client/android → client/web` 的兄弟关系）。新布局下先 `mkdir -p ../web` 再构建，然后把产物拷回本目录：
> `mkdir -p ../web && bash build_apk.sh && mv ../web/dermagent.apk ./dermagent.apk`
> 手机安装后访问 `http://<电脑IP>:8765/`（APK 只是 WebView 壳，界面与数据全部复用 Web 端）。

### 4.4 LangGraph 智能体（TS 编排后端）
```bash
cd DermAgent/web/backend/agent-langgraph
pnpm install && cp .env.example .env   # 填 OPENAI_API_KEY / OPENAI_BASE_URL
pnpm flow "案例1"                       # 本地快检：跑到医生审核 interrupt
pnpm test                              # vitest（50 个测试文件）
```

## 7. 单一真源与后续改动约定

- **规则管线/契约**：`web/backend/shared/derm_core.py` 是唯一权威实现（Win 端经软链复用同一文件，不存在两份副本）。
- **服务层**：`web/backend/server/` 唯一一份，Win 端 `win/backend/server` 只是软链；桌面端自动拉起与 Web 端手动启动用的是**同一份代码、同一个数据目录**。
- **前端**：`web/frontend/` 唯一一份，桌面端与安卓端都复用它。
- **TS 智能体侧**：`web/backend/agent-langgraph/src/app/logic.ts` 与 `derm_core.py` 保持同构（契约 v1.1，snake_case），改契约需三处同步。

仅供医生决策支持演示，不构成诊断或处方；全部为合成/脱敏数据。

## 8. 换电脑部署清单（实测结论）

**结论：能跑，但 venv 与运行时数据不跨机，需要重建。** 按下面顺序做即可。

| # | 事项 | 说明 |
|---|---|---|
| 1 | **软链** | **本目录已附两个一键重建脚本**：`setup-windows.bat`（用 junction + hardlink，免管理员权限）与 `setup-unix-links.sh`。拷过去发现链接失效，跑对应脚本即可 | 1 | **软链** | `DermAgent/` 含 10 条软链。macOS↔LinuxAPFS/NTFS(WSL) 之间拷贝保留；**拷到 Windows 或经 U 盘(exFAT/FAT32)、部分 zip 会失效**。跨平台交付请用「实体化便携版」（见下）或直接拷**原始工作区目录**（无软链） |
| 2 | **Python 环境** | `client/.venv` 是 macOS 版，**不能带走**。新机重建：Python 3.12 + `pip install -r web/backend/requirements.txt`（桌面端另加 `win/frontend/requirements.txt`）。Windows 需 VS C++ 运行库一般已具备；PySide6 官方有 win amd64 wheel |
| 3 | **知识库（407KB，已随包）** | 根目录 `kb-backup-2026-10-23.json` 就是本机 15 本书 / 897 chunk 的完整导出。新机：`curl -X POST http://127.0.0.1:8765/api/kb/restore -H 'Content-Type: application/json' -d @kb-backup-2026-10-23.json`，或界面 ⚙ → 知识库 → 恢复。也可用 `GET /api/kb/backup` 随时重新导出 | 3 | **知识库（416KB 可整包迁移）** | 新机默认空库。用服务层自带通道迁移：`GET /api/kb/backup` → 导出 JSON（含 15 本书的 chunk 与 ready 状态）→ 新机 `POST /api/kb/restore`，或界面 ⚙ → 知识库 → 备份/恢复。也可直接拷 `server/data/rag/books.json` |
| 4 | **向量模型（2.5GB，可不带）** | 不装则**自动降级为纯 BM25 关键词检索**，功能不缺、界面如实标注。新机要混合检索：⚙ → 向量模型 → 选 BGE → 首次联网下载（之后全本地） |
| 5 | **LLM Key** | `server/data/llm_config.json` 属密钥，**不随源码交付**。新机在 ⚙ → LLM 连接 重填端点/Key（或设 `LLM_BASE_URL/LLM_API_KEY/LLM_MODEL` 环境变量）。不配也能演示：走规则稿且界面明确标注「离线演示」，不会伪装 AI 结果 |
| 6 | **历史病例/审计** | `sessions.json`(184KB) 与 `audit.jsonl`(1.5MB) 未交付。要保留演示数据就一并拷 `server/data/`（**注意里面有 Key 文件，外发前先删 `llm_config.json`**） |
| 7 | **3D 资产** | 已随包（`web/frontend/vendor/models` 两份人体 GLB + 语义表 1.6MB）→ **完全离线可用**，只需机器有 WebGL/显卡驱动 |
| 8 | **安卓端** | `MainActivity.java` 里默认地址写死 `http://172.20.10.2:8765/`。换网络/换电脑后 App 首次连接失败会弹地址框（可改并持久化）；要固化新地址就改常量后重跑 `build_apk.sh` |
| 9 | **TS 智能体** | 需 Node ≥ 20 + `pnpm install`（联网）+ `.env` 填 Key；`node_modules` 未交付 |
| 10 | **Windows 打包** | `pyinstaller --name Fuzhi3D --windowed --add-data "web:web" main.py`（**必须在 Windows 上执行**，PyInstaller 不支持交叉打包） |

**离线演示最小集**（断网、无 Key、无向量模型也能完整跑）：`web/frontend/` + `web/backend/server/` + `shared/derm_core.py` + 3D 资产 → 输入「案例1/2/3/4」走内置规则管线。
