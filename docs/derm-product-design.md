# 肤智（DermAgent） — 皮肤科智能问诊与循证辅助智能体 · 产品设计报告

> **版本**：v0.9（比赛提交候选稿） · 日期：2026-09-03
> **副标题**：让医生从「描述哪里不舒服」到「基于证据做判断」更高效。
> **定位声明**：本项目用于 2026 年四川省大学生「智能体+」大赛的技术展示、教学研究和原型验证，**不构成医疗诊断、处方或患者自我诊疗工具**；演示全部使用合成/脱敏数据。

---

## 1. 项目背景和现实痛点

皮肤科门诊量大致使单患者沟通时间有限，长期存在：① 患者对病变部位描述歧义；② 症状、病程、诱因、既往史易遗漏；③ 图片/部位/文字缺少统一关联；④ 医学资料分散，检索核对耗时；⑤ 通用大模型回答无来源、格式不稳、把未知说成确定；⑥ 用药信息需人工核对适应证与禁忌。

肤智（DermAgent） 用「**结构化问诊 + 规则红旗筛查 + 循证引用 + 医生终审**」四道闸口，把大模型约束在决策支持的位置：模型只产出**待审核草稿**，医生对最终结论负全责。

## 2. 目标用户和使用场景

| 用户 | 场景 |
|------|------|
| 皮肤科医生 | 门诊前/中快速整理病例结构，获得带引用的鉴别诊断线索与用药核对项 |
| 实习医生 / 医学生 | 九要素问诊训练、红旗清单自查、观察完整循证决策链路（教学模式） |
| 医疗科研人员 | 固定格式病例摘要与可追溯引用，便于案例整理 |

明确不适用：患者自助问诊、自动诊断、自动开方、急诊决策。

## 3. 产品定位与医疗安全边界

- **定位**：医生决策支持演示原型（女娲智能体 OS 上的可运行智能体 + Windows 演示客户端）。
- **安全边界（硬约束）**：
  1. 不面向患者；输出不构成诊疗建议，界面/报告/视频统一展示免责声明；
  2. 禁止自动处方、剂量、疗程——用药仅输出核对项（适应证/过敏/禁忌/相互作用）且 `requiresDoctorConfirmation=true`；
  3. 一切结果恒为「待审核草稿」，医生确认/修改/拒绝后才可能生成报告；
  4. 引用只能来自本次检索快照，引擎侧白名单校验，编造引用自动剔除并记入不确定性；
  5. `unknown` / `not_asked` 不得解释为「没有」；
  6. 非法 JSON 至多受限修复一次，仍失败标记「未通过系统校验」；
  7. 仅使用合成/脱敏数据，无真实患者隐私。

## 4. 市场 / 竞品与差异化

| 维度 | 通用医疗问答机器人 | 互联网问诊平台 | **肤智（DermAgent）** |
|------|--------------------|----------------|------------|
| 服务对象 | 大众 | 患者↔医生 | **医生/实习医生/医学生** |
| 输出形态 | 自由文本 | 医生人工回复 | **固定 JSON 结构化草稿 + 医生终审** |
| 证据可溯 | 通常无 | 无 | **citation_id+文档名+版本+章节+原文片段，引擎侧白名单强制** |
| 安全拦截 | 弱 | 人工 | **规则红旗筛查（可审计）→ 升级人工审核** |
| 部位表达 | 文字 | 文字+照片 | **结构化九要素 + 脱敏照片说明（+ Windows 3D 定位）** |
| 责任边界 | 模糊 | 医生承担 | **AI 仅草稿，医生确认后才成报告** |

差异化核心：**「可验证引用 + 医生在环 + 规则红旗」三件事同时做进引擎而不是停在提示词**。

## 5. 用户需求与典型案例

需求：结构化九要素采集（身体区域/主诉/症状/病程/变化趋势/诱因/既往史/过敏史/当前用药 + 脱敏照片说明）；必填校验与追问；红旗识别与升级；知识库检索与引用；固定格式输出；医生确认/修改/拒绝；报告生成。

四个内置合成案例（可复现）：

| 案例 | 触发词 | 演示要点 | 预期行为 |
|------|--------|----------|----------|
| 案例1 湿疹样皮疹 | `案例1` | 正常检索与引用 | 完整草稿（complete、routine、带引用）→ 确认 → 报告 |
| 案例2 带状疱疹红旗 | `案例2` | 红旗升级 | RF-HZ-001 命中、severity=needs_review、升级动作展示 → 修改 → 再审 → 确认 |
| 案例3 资料不足 | `案例3` | 追问闭环 | 列缺失项 → 补充合并 → 复检 → 草稿 → 拒绝则不生成报告 |
| 案例4 无答案拒答 | `案例4` | 不足以判断 | 检索 0 命中 → 不编造鉴别诊断/引用 → 建议面诊 |

## 6. 产品流程和界面原型

### 6.1 线上智能体流程（女娲平台，已实现）

```
用户输入（脱敏病例 / 合成案例指令）
 ① intake   合成案例确定性解析 / LLM 九要素抽取（无凭证→规则抽取）
 ② screen   必填校验 + 红旗筛查（规则引擎）
    └ 缺必填 → ask_more（interrupt 追问，最多 2 轮，缺失项结构化列出）
 ③ retrieve 合成知识库检索 → 引用快照（否定词感知，避免「无疼痛」误报）
 ④ analyze  生成待审核草稿（§6.1 固定 JSON；非法 JSON 受限修复一次）
 ⑤ doctor_review 医生审核（interrupt，跨轮等待）
    ├ 确认   → finalize_report 正式报告（流式，含元信息与免责声明）
    ├ 修改   → revise 按意见修订 → 回到 ⑤
    └ 拒绝   → case_closed 终止，不生成报告
```

平台预览会话中：开场白引导 → 发送案例指令或粘贴脱敏病例 → 追问/草稿以消息呈现 → 回复「确认/修改：…/拒绝：…」。

### 6.2 Windows 客户端（阶段 C MVP，已实现）

三栏工作台（PySide6）：**左栏**就诊资料——九要素表单、脱敏照片上传（白名单格式/10MB 上限/EXIF 去标识/本地副本）、合成案例一键导入（案例1–4）；**中栏** 3D 人体定位——Three.js **程序化参数化人体（原创几何体，零外部模型授权风险）**，旋转/缩放、前/后/左/右视角、点击区域选择与高亮、身体区域字段自动填充、截图入报告；WebEngine 不可用时自动降级为下拉选择（瘦环境可演示）；**右栏**智能体结果——待审核草稿卡片（红旗/鉴别诊断/置信度/用药核对/引用原文/元信息）、追问补充、确认/修改/拒绝、报告 Markdown 导出、草稿 JSON 导出。

接入架构：**mock 模式**（默认，完全离线的确定性演示管线——与线上智能体同构的规则逻辑，断网可演示、结果可复现、零密钥）+ **llm 直连模式**（Base URL / API Key / 模型名三个输入框，OpenAI 兼容 `/chat/completions`；LLM 仅负责草稿生成与修订，本地强制保留红旗筛查、知识库检索与引用白名单、非法 JSON 修复一次与降级标记；密钥仅存本机 gitignored 设置文件）+ **http 模式**（POST 到部署方服务端桥接 URL，密钥只在服务端）。任一模式连接失败均明确提示并可切回 mock（断网降级）。操作审计：本地 JSONL 追加记录（`client/data/audit.jsonl`）。顶部常显「仅供医生决策支持」与知识库快照标识。

## 7. 智能体角色和任务编排

计划 §5.2 的逻辑角色与本实现的映射（一条连贯图流程，非独立页面）：

| 计划角色 | 实现 |
|----------|------|
| 接诊采集器 | `intake`（合成案例确定性解析）+ `intake_llm`（LLM 九要素抽取，R-G002 容忍问候语） |
| 资料整理器 | `CaseRecord` 结构化通道 + `mergeCaseReply`（字段：值 合并） |
| 循证检索器 | `retrieve`（关键词计分 + 否定词感知 → 引用快照） |
| 安全审查器 | `screen`（`detectRedFlags` 6 条规则 + `computeMissing` 必填校验） |
| 辅助分析器 | `analyze`（bespoke 两段式：生成 → 受限修复一次，`nodes/analyze.ts`） |
| 输出校验器 | `sanitizeDraftCitations`（枚举收拢、引用白名单、红旗升级强制、元信息强制） |
| 报告助手 | `finalize_report`（`createLlmStreamNode` 流式，R-G009）+ `revise`（按医生意见修订） |
| 医生在环 | `doctor_review`（`createHumanApprovalNode` interrupt/resume，确认/修改/拒绝状态机） |

编排引擎：LangGraph `StateGraph` 显式图（HITL durable stateful flow，interaction=approval），决策逻辑全部抽纯函数（`src/app/logic.ts`）可单测。

## 8. 3D 人体定位与图片工作流（阶段 C MVP，已实现）

- **3D**：Three.js 程序化参数化人体（胶囊/球/盒原创体块，13 个皮肤区域分组：头面部/颈部/躯干/背部/隐私部位/左右上肢/左右手/左右下肢/左右足）——**不依赖外部 GLB 模型，规避授权阻塞（计划 §15 问题 11）**；OrbitControls 旋转/缩放、前后左右视角预设、射线拾取点击选择、选中区域高亮、区域 ID+中文标签经 QWebChannel 回填病例；`preserveDrawingBuffer` 支持视图截图入报告。预留 GLB 加载接口（后续引入正式解剖模型时先登记授权）。
- **图片**：白名单 png/jpg/jpeg/webp、≤10MB；QImage 重编码清除 EXIF；仅保存本地脱敏副本（`client/data/uploads/`），原始图不随病例外发；界面明示「照片仅辅助资料，不代表影像诊断」。
- 智能体侧 `photoNote`（脱敏/合成照片说明）随病例结构化提交并进入引用上下文。

## 9. RAG 知识库、引用和版本管理

- **资料范围**：当前为团队自编、经医学审核的合成演示知识库 3 篇（湿疹样皮炎要点 / 带状疱疹红旗清单 / 问诊与照片规范），`sourceType=authorized_case`；平台搜索确认无已审核医学知识库可登记（关键词：皮肤/医学/湿疹/带状疱疹/诊断，0 命中，见 project.md 门禁记录）。
- **生命周期**：登记（docs/data-license-register.md）→ 审核 → 版本化 → 检索 → 引用 → 下线；快照标识 `synthetic-kb@2026-09-03` 随输出发布。
- **引用实现**：每个章节生成稳定 `citation_id`（如 `CIT-AD-001-S1`），绑定文档名/版本/资料类型/章节/原文片段；**模型只能从检索快照白名单中选择**，`sanitizeDraftCitations` 在引擎侧剔除越界引用（含散落在结论内的 citationIds）并计数记入不确定性。
- **检索质量**：关键词计分 + 否定词感知（「无疼痛」「否认过敏史」不命中），纯函数可回归。

## 10. 固定 JSON 输出和校验机制

草稿契约（schemaVersion 1.0）字段：`caseSummary{selectedBodyRegion,symptomSummary,dataCompleteness}`、`suspectedConditions[]`（confidence 枚举 + supportingEvidence[].citationIds）、`symptomAssessment[]`（status: present|absent|**unknown|not_asked**、basis）、`medicationChecks[]`（itemsToVerify、requiresDoctorConfirmation=true）、`severity.level`（routine|needs_review|urgent|emergency|unknown）、`redFlagEscalation{triggered,reasons,recommendedAction}`、`recommendedNextSteps[]`（urgency）、`uncertainties[]`、`citations[]`、`modelVersion`、`knowledgeSnapshot`、`generatedAt`、`requiresDoctorConfirmation=true`、`status=待审核草稿`。

校验机制（引擎侧强制，不依赖模型自觉）：枚举越界收拢为 unknown；引用白名单过滤并计数；红旗触发强制带升级动作；资料完备度由规则派生；严重程度等级由规则派生（LLM 仅提供 basis 文案）；免责声明/元信息强制注入；非法 JSON 修复至多一次，失败降级规则稿并标记「未通过系统校验」。

## 11. 模型 / API 适配和故障降级

- 模型经运行时适配层接入（provider/baseUrl/apiKeyEnv 可配置，密钥仅环境变量，不入库不入客户端）；当前平台会话注入 OpenAI 兼容端点。
- 降级链：LLM 生成 → 非法 JSON 受限修复一次 → 规则稿（`generatedBy` 标注 `llm / llm-repaired / rule-fallback / llm-invalid`，全程不伪装成功）；无凭证本地演示链路完整可跑。
- 检索无命中 → 「知识库未覆盖，不足以判断」；红旗命中 → 强制升级提示。

## 12. 数据安全、授权和原创性

- 数据：全部合成/脱敏（台账 docs/data-license-register.md 逐条登记来源/许可/审核人/版本）；禁止录入真实患者信息。
- 密钥：仅环境变量（平台受控注入），代码/客户端/视频零密钥。
- 原创性：Git 提交记录、自研 Prompt/Schema/校验器/图编排、平台配置导出留档；3D 模型授权待确认（阻塞项）。

## 13. 技术架构和部署方式

- 女娲智能体 OS（比赛要求入口）：LangGraph TS 显式图（10 节点、3 条条件边、interrupt/resume），checkpointer 持久化支持跨轮/跨重启续跑；ACP surface 对接平台预览会话。
- 结构：`src/core`（契约）→ `src/runtime`（底座，保护）→ `src/libs`（节点工厂）→ `src/app`（业务图/逻辑/知识库）→ `surfaces`（ACP/CLI）。
- **Windows 客户端（已实现，`client/`）**：Python 3.11+ / PySide6（QtWebEngine + QWebChannel 桥）/ Three.js r128（vendored，MIT）/ Pillow（EXIF 脱敏）；PyInstaller 打包（须在 Windows 执行，说明见 client/README.md）。
- 本地运行：`pnpm install && pnpm flow "案例1"`（智能体）；`cd client && pip install -r requirements.txt && python main.py`（客户端，mock 模式离线可跑）。
- 静态三连：`pnpm typecheck && pnpm test && pnpm graph`（智能体）；`python -m pytest client/tests -q`（客户端）。
