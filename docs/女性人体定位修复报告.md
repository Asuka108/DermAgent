## 一、任务背景

客户端原有的人体定位体系（材质型带 + 解剖锚点表 + 校准体系）在男性模型上已稳定，
但女性模型的定位几乎全错。用户要求：

1. **女性人体变为和男性一样的颜色**（白模化，消除材质干扰）；
2. **重新进行人体定位**——为女性模型建立与男性同级的逐面语义表；
3. 此后通过多轮截图目视反馈，逐个修复定位错误；
4. 最后新增需求：**点击头发时不再报「头发」，而是显示被这缕头发遮盖的身体部位**（仅针对女性模型）。

### 安全与工程惯例（全程遵守）

- 客户端不得直连模型供应商 API；LLM 精细化只发几何摘要，禁止 screenshot/image/glb/model_data；LLM 结果仅为待审核草稿。
- 实测校正点必须由用户确认，不擅自定真值（自动生成的锚点表除外）。
- `face-semantics.json`（男性）不得手改编码人工区域。
- 诚实性：证据不足如实报「无法可靠识别」，不伪造；不注册 0 面幽灵标签。
- verify 必须用 `./.venv/bin/python`（系统 python3 无 PySide6）。
- 会话惯例：「打开windows端」= 后台启动 `./.venv/bin/python main.py`，用户自行目视检查。
- 每次修复必须通过全量回归（`tools/verify_3d.py`，EXIT=0）后才重启客户端交付。

## 三、技术架构要点

### 3.1 坐标系统（构建器 ↔ 运行时一致，已验证）

- 换算公式：**世界 = 局部 × scale + off**；
- 女性模型 scale = 2.765909，off = [−0.387, −2.5242, −0.035]；
- 运行时 `registerHuman`：scale = 5/size.y，pos.x/z = −center·scale，pos.y = −2.5 − min.y·scale（v28 缩放感知修复）；
- 运行时局部坐标 = `modelRoot.worldToLocal`（main.js:988）；
- boneBox 无骨骼时回退顶点包围盒，与构建器 `glb_io.register_transform` 一致。

### 3.2 女性实测地标（世界系，5 单位身高）

| 地标 | 值 | 地标 | 值 |
|---|---|---|---|
| neck_y | 1.762 | jaw_y（=neck_y+0.18） | 1.942 |
| shoulder_y | 1.471 | 颈底（neck_y−0.10） | 1.662 |
| waist_y | 0.681 | eye_y（锚点） | 2.134 |
| hip_y | −0.109 | upper_lip_y（锚点） | 1.947 |
| chest_y | 0.949 | **briefs_ymid（骶臀分界）** | **0.194** |
| knee_y | −1.150 | ankle_y | −2.130 |
| 内裤 y 范围 | [−0.104, 0.493] | 内裤 half | 0.468 |

臂轴：S(0.39, 1.365, 0.001) → F(1.742, 0.138, 0.066)，wrist_t=0.758，elbow_t=0.379。

### 3.3 fsem JSON schema

```json
{
  "model": "...", "sha256_prefix": "...", "version": "...",
  "generated_by": "...", "fit_info": {...},
  "meshes": { "<运行时mesh名>": { "faces": N, "segments": [[start, end, zoneId], ...] } },
  "labels": { "<zoneId>": { "zh": "...", "conf": 0.9, "cat": "...", "note": "..." } }
}
```

当前状态（阶段⑦后）：**31 meshes / 129,340 faces / 158 labels**。

### 3.4 onPick 优先级链（web/main.js）

```
REGION_DRAW → CALIB → WIZARD → manual → measuredFace → measuredCorrection
→ fsem（逐面语义表） → 材质兜底（头发/衣物） → anat（解剖锚点） → zone（型带）
```

- 运行时 source 字符串：`逐面语义表（真实网格三角面）`；
- 衣物/内裤覆盖在 fsem 结果后加「（内裤覆盖）/（衣物覆盖）」后缀；
- 发片命中现在直接由 fsem 表返回「…（发覆盖）」标签。

### 3.5 验证体系（tools/verify_3d.py）

1. **男性基线**：v18 断言（区域删净、解剖语义、型带、onPick 链、视角稳定…）；
2. **女性断言**：19 锚点 + z_band + 胸型带 + 向导 7 点 + 眼/趾/发片/衣物真实点击；
3. **双视角点击普查**：对每个 zone 的样本点做真实射线点击（先 front 视角 5 偏移轮询，
   zh 前缀未命中换 back 视角重试；两次都未直中交 Python 兜底判定）；
   样本可见视角由实测决定，不依赖构建器法线猜测；
4. **切回男性零回归**复核；
5. 通过后截取 front/back 截图存档。

诊断方法论：**extent 探针**（`tools/probe_zone_extent.py`，输出每 zone 的 n/mean/min/max）
+ 局部↔世界换算 + 边界值计算，判定「点击错位」是表 bug 还是前景遮挡。

## 四、逐项修复记录

### 阶段①②③：白模化 + 逐面语义表 + 回归全绿（压缩前完成）

- 女性模型材质统一为男性同款肤色（白模化）；
- 构建器按材质语义网格边界（Arms/Legs/Torso/Face/Ears/Lips/Teeth/Fingernails/Toenails/

- 回归全绿（EXIT=0），客户端重启交付。

### 阶段④：用户反馈 1 ——「这个位置应该是左手大臂」

- **现象**：点击左臂上部（局部 (0.335, 1.364, −0.088) / (0.380, 1.381, −0.083)）报「左肩（三角肌区）」。
- **诊断**：肩/大臂分界旧规则 `tn < 0.14` 过宽（下探 y=1.202），把腋下整段大臂划进肩部。
- **修复**（classify_arms）：分界改为**腋平面**（过臂轴起点 S 的垂面，tn=0）：
  ```python
  f.setid(idx[tn < 0], Z("shoulder_up_" + v, zh + "肩（三角肌区）", ...))
  m_ua = (tn >= 0) & (tn < et - 0.035)
  ```
- **验证**：shoulder_up_l 151 面（y≥1.292）、upper_arm_l 573 面（上缘 y=1.460）；
  用户原点击 tn=0.105/0.138 → 上臂 ✓。回归全绿后交付。

### 阶段⑤：用户反馈 2 ——「这里明显不对，这里是屁股」

- **现象**：点击臀部（局部 (0.191, 0.936, −0.127) / (0.081, 0.952, −0.126)）报「会阴周围（内裤覆盖）」。
- **诊断**：classify_briefs 的 `fill_rest` 兜底吃掉臀部主体（602 面）。
- **修复**（classify_briefs）：新增臀部主体分侧规则，臀沟收窄 |x|<0.055：
  ```python
  f.set(back & (C[:,1] <= LM["briefs_ymid"]) & (C[:,0] >= 0.055),
        Z("briefs_buttock_l", "左臀（内裤覆盖）", 0.8, "garment"))
  f.set(back & (C[:,1] <= LM["briefs_ymid"]) & (C[:,0] <= -0.055),
        Z("briefs_buttock_r", "右臀（内裤覆盖）", 0.8, "garment"))
  ```
- **验证**：briefs_buttock_l/r 各 276 面，会阴周围缩到 208 面。回归全绿后交付。

### 阶段⑥：用户反馈 3 ——「这里明显还是屁股」

- **现象**：点击臀下部（内裤腿缘以下裸露皮肤，局部 (0.185, 0.891, −0.110) /
  (0.097, 0.889, −0.109)，世界 y≈−0.060/−0.065）报「腰/背（下）」。
- **诊断**：躯干网格臀区上界 `hip_y+0.02 = −0.089` 太低，腰/背（下）一直延伸到这里；
  且与内裤层臀区上界 briefs_ymid=0.194 不一致。
- **修复**（classify_torso）：皮肤层臀区上界对齐**骶臀分界线** briefs_ymid（与内裤层同一条线）：
  ```python
  butt_line = LM["briefs_ymid"]
  f.set(back & (C[:,1] <= waist_y) & (C[:,1] > butt_line),
        Z("back_lower_waist", "腰/背（下）", 0.8, "torso"))
  f.set(back & (C[:,1] <= butt_line) & (np.abs(C[:,0]) < 0.055),
        Z("gluteal_cleft", "臀沟（臀裂壁）", 0.85, "body"))
  for v in ("l", "r"):
      f.set(back & (C[:,1] <= butt_line) & (sd == v),
            Z("buttock_" + v, SIDE_ZH[v] + "臀", 0.9, "body"))
  ```
- **验证**：
  - 表重建后 148 labels；`back_lower_waist` y∈[0.198, 0.680]（不再下探到臀）；
  - `buttock_l/r` 各 224 面（y 上界 = 0.195 = butt_line），用户点击点落入范围；
  - `gluteal_cleft` 从 0 面幽灵复活（96 面，|x|<0.055）。
  - 回归全绿（148/148 区点击普查通过）后交付。

## 五、关键经验与陷阱

1. **checker source 判断**：运行时 source 是 `逐面语义表（真实网格三角面）`，不是 `fsem`，
   必须用 `startswith("逐面语义表")` 判断。
2. **`_phalanx_` 前缀 bug**：zone id 是 `proximal_phalanx_l_middle`（以 proximal_ 开头），
   应判 `"_phalanx_" in zid` 而非 startswith。
3. **单面法线定视角不可靠**：肘窝/踝前位置偏后朝前（背视点击必被遮挡）；唇内面/牙齿混合法线
   曾致左右不对称。最终方案：**双视角实测**（JS 先 front 后 back 重试），不依赖构建器猜测。
4. **probe 旧缓存误读**：重建表后必须重跑 `probe_zone_extent.py`，否则看到的是旧 extent 数据。
5. **probe NameError: A_ANCH**：classify 用模块全局 A_ANCH，外部复用需注入
   `B.A_ANCH = {...}` 并调用 `B.measure_landmarks(prims, B.A_ANCH, A_chest)`；sink 切片 `[:, :3]`。
6. **Filler 语义**：`set()` 只填未分配面（顺序、首中为准）；分类器结束时必须无剩余，
   否则产生幽灵标签（如修复前的 gluteal_cleft）。
7. **客户端旧标记**：旧选中标记是点击当时的记录，表更新后仍显示旧标签——
   每次交付都提醒用户**先删除旧标记再验证**。
8. **权限分类器偶发不可用**：Bash 调用被拒时等待后重试即可（读操作不受影响）。
